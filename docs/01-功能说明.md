# 功能说明

本文档描述 HomeKeeper 的功能范围、数据模型与典型使用流程，是理解系统的入口。

---

## 一、功能清单

| 功能 | 说明 | 对应 API / 页面 |
|------|------|----------------|
| 注册账号 | 用户名 + 密码，密码 bcrypt 哈希存储 | `POST /api/auth/register` |
| 登录获取令牌 | 返回 JWT，后续请求带 `Authorization: Bearer <token>` | `POST /api/auth/login` |
| 当前用户 | 校验令牌并返回用户信息 | `GET /api/auth/me` |
| 物品增删改查 | 名称/描述/数量/单位/状态/保质期/购买日期/位置/分类 | `/api/items` |
| 位置层级管理 | 层级树（parent_id），删除父级时子级自动提升一级 | `/api/locations` |
| 分类管理 | 带颜色标签 | `/api/categories` |
| 概览统计 | 总数、按状态分布 | `GET /api/dashboard/summary` |
| 过期提醒 | 近 N 天即将过期的物品 | `GET /api/dashboard/expiring?days=30` |

---

## 二、数据模型

> 所有业务数据带 `owner_id`，实现多用户隔离。时间字段为服务端时区。

| 模型 | 关键字段 | 说明 |
|------|---------|------|
| **User** | `id, username(unique), hashed_password, created_at` | 账号 |
| **Location** | `id, name, parent_id(FK 自引用), note, owner_id` | 层级位置 + 备注 |
| **Category** | `id, name, color, owner_id` | 分类/标签 |
| **Item** | `id, name, description, location_id, location_note, category_id, quantity, unit, status, expiry_date, purchase_date, owner_id, created_at, updated_at` | 核心实体 |
| **ItemStatus** | 枚举：`在库 / 已借出 / 损坏 / 待处理 / 已丢弃` | 状态字典，见下 |

### 关系

```
User 1 ── * Item / Location / Category
Location 1 ── * Location (自引用 parent_id，层级树)
Item ── Location (location_id)
Item ── Category (category_id)
Item ── location_note (自由备注，与层级位置互补)
```

---

## 三、状态字典（ItemStatus）

| 值 | 含义 |
|----|------|
| `在库` | 正常存放 |
| `已借出` | 被借走，不在手中 |
| `损坏` | 损坏不可用 |
| `待处理` | 待维修/待处置 |
| `已丢弃` | 已丢弃/消耗完 |

> 扩展状态：在 `app/models/status.py` 的 `ItemStatus` 枚举中增加值即可，前后端同步。

---

## 四、典型使用流程

1. **注册 / 登录**：浏览器打开首页 → 跳登录页 → 注册 → 自动登录。
2. **建位置层级**：位置页添加「厨房」→ 添加「冷藏柜」并填父级 ID=厨房。
3. **建分类**：分类页添加「食品」「工具」并选颜色。
4. **记物品**：物品页填写名称、选位置、填备注位置、选分类、数量、状态、保质期。
5. **看概览**：概览页查看总数、状态分布、近 30 天过期提醒。
