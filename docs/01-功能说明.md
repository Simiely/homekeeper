# 功能说明

本文档描述 HomeKeeper 的功能范围、数据模型与典型使用流程，是理解系统的入口。

---

## 一、功能清单

| 功能 | 说明 | 对应 API / 页面 |
|------|------|----------------|
| 注册账号 | 用户名 + 密码，密码 pbkdf2 哈希存储 | `POST /api/auth/register` |
| 登录获取令牌 | 返回 JWT，后续请求带 `Authorization: Bearer <token>` | `POST /api/auth/login` |
| 当前用户 | 校验令牌并返回用户信息 | `GET /api/auth/me` |
| 物品管理 | 增删改查，含名称/描述/数量/单位/状态/保质期/购买日期/位置/分类 | `/api/items` |
| 物品搜索 | 按关键词（名称/描述/备注）、状态、分类、位置、标签四维+组合筛选 | `GET /api/items?keyword=&status_filter=&category_id=&location_id=&tag_id=` |
| 物品分页 | 每页 N 条，翻页导航 | `GET /api/items?page=1&page_size=20` |
| 物品编辑 | 每行「编」按钮，表单回填，提交时只发送变化的字段 | `PUT /api/items/{id}` |
| 位置层级树 | 可视化树视图 + 缩进下拉选择器，删除父级时子级自动提升一级 | `/api/locations` |
| 分类管理 | 带颜色标签，支持编辑 | `/api/categories` |
| 标签管理 | 多对多标签系统，一个物品可打多个标签，支持编辑 | `/api/tags` |
| 物品-标签关联 | 表单多选标签添加，支持筛选标签 | `POST/DELETE /api/items/{id}/tags/{tag_id}` |
| 图片上传 | 拍照上传 → 自动 WebP 压缩 → 超 2000px 缩放 → 缩略图预览 | `POST/GET/DELETE /api/items/{id}/images` |
| 概览统计 | 总数、按状态分布、按分类分布 | `GET /api/dashboard/summary` |
| 过期提醒 | 近 N 天即将过期的物品（天数可调） | `GET /api/dashboard/expiring?days=N` |
| 推送通知 | Web Push 推送，3 天前自动提醒过期物品 | `Web Push API` |
| 企业微信推送 | 过期提醒推送到企业微信群（规划中） | 企业微信 Webhook |
| 群交互 | 群内自然语言查询/修改物品（规划中） | 企业微信回调 |
| PWA 支持 | 添加到主屏幕，离线图标 | `manifest.json + service-worker.js` |

## 二、数据模型

> 所有业务数据带 `owner_id`，实现多用户隔离。时间字段为服务端时区。

| 模型 | 关键字段 | 说明 |
|------|---------|------|
| **User** | `id, username(unique), hashed_password, created_at` | 账号 |
| **Location** | `id, name, parent_id(FK 自引用), note, owner_id` | 层级位置 + 备注 |
| **Category** | `id, name, color, owner_id` | 分类/标签（单选）|
| **Tag** | `id, name, color, owner_id` | 标签（多对多）|
| **Item** | `id, name, description, location_id, location_note, category_id, quantity, unit, status, expiry_date, purchase_date, owner_id, created_at, updated_at` | 核心实体 |
| **ItemImage** | `id, item_id(FK), filename, original_name, width, height, file_size` | 物品图片（一对多）|
| **PushSubscription** | `id, user_id(FK), endpoint, auth_key, p256dh_key` | Web Push 订阅 |
| **ItemStatus** | 枚举：`在库 / 已借出 / 损坏 / 待处理 / 已丢弃` | 状态字典 |

### 关系

```
User 1 ── * Item / Location / Category / Tag / PushSubscription
Location 1 ── * Location (自引用 parent_id，层级树)
Item ── Location (location_id, ondelete=SET NULL)
Item ── Category (category_id, ondelete=SET NULL)
Item ── * Tag (多对多，通过 item_tags 关联表)
Item ── * ItemImage (一对多，ondelete=CASCADE)
Item ── location_note (自由备注，与层级位置互补)
```

## 三、状态字典（ItemStatus）

| 值 | 含义 |
|----|------|
| `在库` | 正常存放 |
| `已借出` | 被借走，不在手中 |
| `损坏` | 损坏不可用 |
| `待处理` | 待维修/待处置 |
| `已丢弃` | 已丢弃/消耗完 |

> 扩展状态：在 `app/models/status.py` 的 `ItemStatus` 枚举中增加值即可，前后端同步。

## 四、典型使用流程

1. **注册 / 登录**：浏览器打开首页 → 跳登录页 → 注册 → 自动登录。
2. **建位置层级**：位置页添加顶层位置 → 添加子位置（下拉选择父级）。
3. **建分类**：分类页添加「食品」「工具」并选颜色。
4. **建标签**：标签页添加「易碎」「贵重」「需冷藏」等。
5. **记物品**：物品页填写名称、选位置、选分类、选标签、数量、状态、保质期、上传图片。
6. **编辑物品**：物品列表点「编」→ 表单回填 → 改 → 保存。
7. **筛物品**：按关键词、状态、分类、位置、标签组合筛选。
8. **翻页**：物品多时通过页码导航浏览。
9. **看概览**：概览页查看总数、状态分布、分类分布、过期提醒（天数可调）。
10. **收推送**：允许通知后，物品过期前 3 天自动收到浏览器推送。
