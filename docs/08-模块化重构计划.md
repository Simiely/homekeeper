> 版本：v1（2026-08-01）· 状态：待评审
> 本文档基于对 `app/`（42 个 Python 文件）与 `static/`（13 个 JS 模块 + 2 个 HTML）的全面梳理。

## 一、现状架构

```
app/
├── main.py                 # 入口：挂载 13 个 router + 静态目录 + lifespan 调度
├── config.py               # pydantic-settings 配置（含 [local-dev] 本地路径适配）
├── database.py             # 引擎/会话/Base（含 sqlite 相对路径→绝对路径解析）
├── deps.py                 # get_current_user / get_admin_user 依赖
├── models/                 # 10 个模型 + item_tag 关联表
├── schemas/                # 各实体 Pydantic schema
├── core/security.py        # JWT + passlib 密码哈希
├── routers/                # auth/items/locations/categories/tags/dashboard/push/admin/images/borrow/data
├── services/               # audit.py（ORM 事件日志）、backup.py（备份 + 定义了自己的 router！）
└── static/                 # 前端：index.html/login.html + js/（13 模块）+ css/style.css
```

**前端模块**：`api.js`（请求封装）· `app.js`（导航调度）· `theme.js`（主题）· `utils.js`（工具）· `auth.js`（登录页）· 7 个视图模块（dashboard/items/locations/categories/tags/backups/admin）

## 三、模块化重构计划

> 原则：**先修 bug 止血，再动结构；每阶段可独立交付、可回归验证**。
> 后端分层目标：`routers（HTTP 层）→ services（业务层）→ models（数据层）`，单向依赖，禁止反向。

### 阶段 A：止血（P0 四项，改动小、收益大）

| 步骤 | 目标 | 改动文件 | 验收标准 |
|------|------|----------|----------|
| A1 | 修复概览页崩溃 | `static/js/dashboard.js`：遍历改 `items.items`，并直接复用后端 `/dashboard/summary` 的按分类聚合（删掉前端重复统计） | 概览页正常显示总数/状态/分类统计 |
| A2 | 修复导出 CSV | `static/js/items.js` + `static/js/api.js`：新增 `download()` 方法（fetch+blob+token），替换 `window.open` | 点击导出下载成功，内容含全部物品 |
| A3 | 图片接口加鉴权 | `routers/images.py`：`serve_image` 挂 `get_current_user`（校验 item 归属或管理员） | 无 token=401；他人图片 403 |
| A4 | 消除双重日志 | `routers/items.py`：删除手动 `_log_item` 调用，保留 `services/audit.py` 事件监听；`models/item_log.py` 的 FK 改 `ondelete="SET NULL"` 保住删除日志 | 操作仅落 1 条日志；删除物品后日志保留 |

### 阶段 B：分层与去重（P1 模块化核心）

| 步骤 | 目标 | 改动文件 | 验收标准 |
|------|------|----------|----------|
| B1 | 调度器收敛 | 新建 `app/services/scheduler.py`：统一管理 push/backup 两个 BackgroundScheduler 的 start/stop；`services/backup.py` 移除对 `routers/push` 的导入 | `main.py` lifespan 只调 scheduler 入口；无 services→routers 反向依赖 |
| B2 | services 层去 router 化 | 新建 `routers/backup.py` 承接备份 API；`services/backup.py` 只留业务函数 | `app/` 内所有 `APIRouter` 只存在于 `routers/` |
| B3 | 备份/恢复健壮化 | `services/backup.py`：restore 时暂停 backup 调度器；用 `sqlite3` 原子备份或恢复后 `PRAGMA integrity_check`；`DB_PATH` 统一从 `config` 取 | 恢复期间无并发写；恢复后校验通过 |
| B4 | Schema 规范化 | `schemas/__init__.py` 补全导出；`BorrowCreate.borrow_date` 改 `date`；`routers/borrow.py` 删手写解析 | 非法日期返回 422 而非 500；所有 schema 可从包导入 |
| B5 | 删除用户健壮化 | `routers/admin.py` + `models/user.py`：用户删除前将名下物品 `owner_id` 置 NULL 或转交管理员，或加级联策略 | 删除用户不再 500 |
| B6 | CSV 导入事务化 + 状态常量 | `routers/data.py`：导入循环加 `rollback`；状态值引用 `ItemStatus` 枚举 | 失败批不产生半提交数据 |

### 阶段 C：前后端状态统一与常量收敛（P1 延续）

| 步骤 | 目标 | 改动文件 | 验收标准 |
|------|------|----------|----------|
| C1 | 状态字典单源 | 后端 `models/item.py` 定义 `ItemStatus` 枚举；新增 `GET /api/meta` 返回状态/单位等字典；前端 `items.js` 的 `STATUS_OPTIONS` 改从 `/api/meta` 拉取 | 前后端状态值只在一处定义；新增状态只改一处 |
| C2 | 前端重复逻辑收敛 | `static/js/locations.js` 复用 `utils.js` 的 `buildTreeOptions`；新增 `utils.js` 的 `viewError(view, msg)` / `viewLoading(view)` 公共模板，7 个视图模块统一替换 | 无重复树构建代码；视图错误样式一致 |

### 阶段 D：低优加固（P2，可选分批）

| 步骤 | 目标 | 改动文件 |
|------|------|----------|
| D1 | 数据库路径解析兜底 | `database.py`：覆盖 `sqlite:///data/...` 等全部相对形式 |

| D6 | items.js 拆分 | 按「列表渲染 / 表单 / 弹窗（日志·借用·二维码·图片）」拆分为独立模块 |

## 四、建议执行顺序

```
阶段 A（止血，4 步）→ 回归测试 → 阶段 B（分层，6 步）→ 回归测试
→ 阶段 C（统一，2 步）→ 阶段 D（加固，分批）
每完成一个阶段：pytest + 浏览器手工冒烟（登录/概览/物品增删改/导出/备份）
```

> 全部完成后预期：`routers` 只做 HTTP 编排、`services` 只做业务、`models/schemas` 单一职责；前端视图模块间无重复代码，状态字典单源；无越权/崩溃类 bug。

## 六、位置拖拽改造（SortableJS 方块卡片，2026-08-01）

> 需求：位置管理改为**方块卡片**展示，支持**拖拽调整父子/顺序关系**（替代原文本层级树）。

### 方案选型
- 调研结论：SortableJS 是原生 JS 场景唯一"零依赖 + 官方嵌套树拖拽"的主流方案（React 系 dnd-kit / Vue 系 Draggable 不适用）；`locations` 表本身是 `parent_id` 自引用扁平结构，与推荐数据模型一致。

### 改动清单
| 文件 | 改动 |
|------|------|
| `static/vendor/sortable.min.js` | 新增，SortableJS 1.15.6 本地化（离线可用，不依赖外网 CDN） |
| `static/index.html` | 引入 vendor 脚本（app.js 之前） |
| `models/location.py` | 新增 `sort_order` 列（同级排序） |
| `schemas/location.py` | `LocationOut` 加 `sort_order`；新增 `LocationReorderItem` |
| `routers/locations.py` | 新增 `PUT /api/locations/reorder` 批量保存（归属校验 + 父位置校验 + **环检测**）；列表按 `parent_id, sort_order` 排序；创建位置自动排同级末尾 |
| `database.py` | `_migrate_sqlite()` 轻量迁移：既有库 `ALTER TABLE locations ADD COLUMN sort_order` |
| `static/js/locations.js` | 重写：方块卡片递归渲染 + Sortable 嵌套实例（统一 group、handle 拖拽手柄）+ onEnd 解析 DOM 新结构自动保存 + 失败回滚 |
| `static/css/style.css` | `.loc-list/.loc-card/.loc-handle/.loc-children` 等方块卡片与拖拽反馈样式 |
| `tests/test_locations.py` | 新增 4 个测试：正常重排 / 环检测 / 越权 / 新位置排序 |

### 关键设计
- **保存时机**：松手自动保存（`PUT /reorder` 一次提交全量扁平结构），顶部短暂提示"已保存"；失败自动回滚重渲染
- **环检测**：基于「数据库现有关系 + 本次新结构」合并追溯（链路可能跨越 payload 之外的节点，不能只查当次请求）
- **交互**：拖拽手柄 `≡` 限定拖动（避免误触删除按钮）；拖入卡片内=变子级、拖到边缘=变同级；幽灵占位 + 虚线引导线

### 验证
- pytest **12 passed**（新增 4 个位置测试）
- 接口实测：正常重排 ✓ / 跨节点环检测 400 ✓ / 越权 400 ✓ / 迁移加列 ✓
