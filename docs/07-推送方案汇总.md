# 推送方案汇总

> 当前采用 **Web Push（浏览器推送）**，其他方案按需切换。

---

## 当前方案：Web Push（已实现）

**v0.5.0 已实现**，无需额外配置。

### 工作原理

```
APScheduler（每 6 小时扫描过期物品）
  → 查出过期物品
  → 推送到浏览器 Service Worker
  → 桌面/手机通知栏弹出提醒
```

### 用户端操作

```
首次登录 HomeKeeper → 顶部栏显示 🔕
  → 点击 → 浏览器弹「允许通知？」→ 允许
  → 变成 🔔
之后有物品过期 → 浏览器自动弹通知
```

### 支持范围

| 设备 | 支持情况 | 操作 |
|------|---------|------|
| 桌面 Chrome | ✅ 稳定 | 允许通知即可 |
| iOS Safari | ✅（16.4+）| 添加到主屏幕 → 允许通知 |
| Android Chrome | ⚠️ 需手动设置 | 允许通知 + 关电池优化 |

### 不需要的配置

`SERVERCHAN_SENDKEY`、`WECOM_*` 等配置项已全部移除。

---

## 备选方案（后续评估）

| 方案 | 说明 | 适用场景 | 复杂度 |
|------|------|---------|--------|
| **APK 轮询** | 安卓 App 定时调 API 弹本地通知 | 自己做 APK 时顺带实现 | ⭐⭐ |
| **企业微信自建应用** | 官方 API 发应用消息到微信 | 不想依赖第三方 | ⭐⭐⭐ 需配 IP 白名单 |
| **企业微信群机器人** | Webhook 发到企业微信群 | 需要发群消息（限内部群）| ⭐ |
| **Server酱** | 第三方推送服务 | 不想自建、接受第三方 | ⭐ 扫码即用 |
| **WebSocket 自建** | APK 和服务器长连接实时推送 | 需要实时推送 | ⭐⭐⭐ |
