# 踩坑与排错（TROUBLESHOOTING）

记录开发 / 部署中遇到的真实问题。**遇到新坑请追加到对应条目或新增条目**，方便回溯。

---

## 1. SQLite + Docker 卷写入权限

- **现象**：容器内报 `sqlite3.OperationalError: unable to open database file` 或只读错误。
- **根因**：宿主机 `./data` 挂载进容器后，容器内进程（非 root 或权限不匹配）无写权限。
- **方案**：`Dockerfile` 中 `RUN mkdir -p /app/data && chmod 777 /app/data`；`docker-compose.yml` 用 `./data:/app/data` 持久化。本地直接运行时确保 `data/` 目录存在且可写。

## 2. 静态文件与 `/api` 路由冲突

- **现象**：访问 API 返回 HTML，或前端资源 404。
- **根因**：`StaticFiles` 挂载在 `/` 会兜底所有未匹配路径，若在 API 路由**之前**挂载会吞掉 `/api/*`。
- **方案**：`app.mount("/", StaticFiles(...))` **必须放在所有 `include_router` 之后**（`app/main.py` 已是此顺序）。

## 3. CORS 跨域（安卓端远程调用）

- **现象**：浏览器/安卓端调 API 报 CORS 错误，或带凭据时被浏览器拒绝。
- **根因**：`allow_credentials=True` 与 `allow_origins=["*"]` 同时存在时，带凭据的请求会被浏览器拒绝。
- **方案**：同源（网页与 API 同域）无影响；安卓端跨域时把 `.env` 的 `CORS_ORIGINS` 设为具体域名（逗号分隔），**不要**用 `*`。生产环境务必收紧。

## 4. passlib + bcrypt 版本兼容（已解决）

- **现象**：`passlib 1.7.4` + `bcrypt 5.0` 下，注册/登录抛 `ValueError: password cannot be longer than 72 bytes`，并伴随 `AttributeError: module 'bcrypt' has no attribute '__about__'` 警告。
- **根因**：bcrypt 5.x 改了底层 API 且强制 72 字节限制，passlib 1.7.4（多年未更新）未能适配，错误构造了待哈希内容。
- **方案（已采用）**：改用 passlib 内置 `pbkdf2_sha256`，不依赖外部 `bcrypt`，无长度限制。`app/core/security.py` 中 `CryptContext(schemes=["pbkdf2_sha256"])`；`requirements.txt` 仅保留 `passlib>=1.7.4`（去掉 `[bcrypt]`）。
- 若坚持 bcrypt，可固定 `bcrypt==4.0.1`；但 pbkdf2 对本项目（本地/内网）已足够安全且零外部依赖。

## 5. JWT 过期与刷新

- **现象**：登录一天后请求 401。
- **根因**：`ACCESS_TOKEN_EXPIRE_MINUTES` 默认 1440（1 天），当前无刷新令牌。
- **方案**：延期可改 `.env` 的 `ACCESS_TOKEN_EXPIRE_MINUTES`；长期方案可在后续版本引入 refresh token（至今未实现）。

## 6. 日期 / 时区

- **现象**：保质期显示偏差或解析失败。
- **根因**：`expiry_date` 用服务端 `date`（无时区），前端传 ISO 字符串（`YYYY-MM-DD`）；FastAPI 按服务端时区解释。
- **方案**：前端 `<input type="date">` 直接提交 ISO 字符串即可；多时区场景需后续统一时区处理。

## 7. pydantic-settings 读取 `.env`

- **现象**：本地改了 `.env` 不生效。
- **根因**：`Settings` 优先读**环境变量**（docker-compose 的 `environment`）；`.env` 仅本地未设环境变量时生效，且路径相对**工作目录**（`/app`）。
- **方案**：容器部署改 `docker-compose.yml` 的 `environment`；本地改 `.env` 需从项目根目录启动。

## 8. 中文枚举值存储

- **现象**：状态字段存入/读出异常。
- **根因**：`ItemStatus` 用 `str, enum.Enum`，值为中文（`"在库"` 等）。SQLAlchemy 存字符串值，Pydantic 按值匹配。
- **方案**：保持前后端都用同一套中文值；新增状态在 `app/models/status.py` 枚举中增加即可，前端由 `GET /api/meta` 单源拉取（`items.js` 仅保留离线兜底值）。

## 9. JavaScript Temporal Dead Zone（TDZ）

- **现象**：页面加载后物品视图空白，控制台报 `ReferenceError: cannot access 'currentPage' before initialization`。
- **根因**：`let currentPage = 1` 声明在 `loadItems()` 调用之后。`let`/`const` 有暂时性死区（TDZ），在声明前访问会抛 ReferenceError。
- **方案**：所有 `let`/`const` 变量声明必须在**首次使用之前**。函数调用时如果引用了某变量，该变量的 `let`/`const` 声明必须在调用之前。`function` 声明会提升，但内部读取的 `let` 变量受 TDZ 约束。

```javascript
// ❌ 错误：loadItems() 引用了 currentPage，但声明在调用之后
loadItems();
let currentPage = 1;

// ✅ 正确：声明在调用之前
let currentPage = 1;
loadItems();
```

## 10. SQLAlchemy 外键 ondelete 行为

- **现象**：删除分类或位置时抛 500，`FOREIGN KEY constraint failed`。
- **根因**：`Item` 表的 `category_id` 和 `location_id` 外键未设 `ondelete`，SQLite 默认拒绝删除被引用的行。
- **方案**：根据业务场景选择策略。本项目中删分类/位置时希望物品保留（仅解除关联），用 `ondelete="SET NULL"`。若要级联删除用 `ondelete="CASCADE"`。

```python
# 使用 SET NULL：删分类后物品的 category_id 自动变为 NULL
ForeignKey("categories.id", ondelete="SET NULL")
```

## 11. 数据库会话泄漏（Session Leak）

- **现象**：后台调度任务异常时日志无报错，但 SQLite 连接数持续增长。
- **根因**：`db.close()` 在 `try` 块内，`except` 捕获异常后 `close` 被跳过。
- **方案**：用 `try/finally` 或在上下文管理器中关闭。`finally` 块无论是否异常都会执行。

```python
db = None
try:
    db = SessionLocal()
    # ... 业务逻辑 ...
except Exception:
    logger.exception("出错")
finally:
    if db is not None:
        db.close()
```

## 12. CORS `allow_credentials` + `allow_origins=*` 冲突

- **现象**：前端请求带 `Authorization` 头时报 CORS 错误。
- **根因**：CORS 规范明确禁止 `Access-Control-Allow-Origin: *` 与 `Access-Control-Allow-Credentials: true` 同时存在。
- **方案**：本项目前端与 API 同域部署（`StaticFiles mount`），不需要 `allow_credentials`；移除即可。如需跨域带凭据，必须把 `allow_origins` 设为具体域名。

## 13. Python 模块循环导入（Circular Import）

- **现象**：`Item` 和 `Tag` 互相引用导致启动报 `ImportError` 或 `AttributeError`。
- **根因**：多对多关系中两个模型互相 `relationship`，直接 import 对方造成循环。
- **方案**：使用字符串 forward reference `"Tag"` 而非 `Tag`。Pydantic schema 中同理使用 `list["TagBrief"]`。关联表通过 `secondary=item_tag_assoc` 在运行时绑定，不依赖导入顺序。

## 14. Pydantic `from_attributes` 缺失

- **现象**：`ValidationError: Input should be a valid dictionary or instance of XxxSchema`
- **根因**：Pydantic v2 的 schema 默认只接受 dict，不接受 ORM 对象。需要显式加 `model_config = ConfigDict(from_attributes=True)`。
- **方案**：所有用于响应（`response_model`）的 schema 必须加 `from_attributes=True`。如果嵌套子 schema，子 schema 也需要加上。

```python
class TagBrief(BaseModel):
    model_config = ConfigDict(from_attributes=True)  # 必须
    id: int
    name: str
    color: str
```

## 15. 前端 ES Module 共享函数

- **现象**：`escapeHtml()` 在 5 个 JS 文件里重复定义，改动需改 5 处。
- **根因**：每个 JS 模块各自定义工具函数，没有集中管理。
- **方案**：将共用函数提取到 `utils.js`，其他模块通过 `import` 引用。`<script type="module">` 原生支持 ES Module 的 `import/export`。

```javascript
// utils.js
export function escapeHtml(s) { ... }

// items.js
import { escapeHtml } from "./utils.js";
```

## 16. PWA manifest.json 图标缺失

- **现象**：添加到主屏幕后 App 图标为空白/默认图标。
- **根因**：`manifest.json` 的 `icons` 数组为空。
- **方案**：至少提供一个 192x192 的 SVG 或 PNG 图标。SVG 适合作为 PWA 图标。

## 17. APScheduler 与 FastAPI lifespan 集成

- **现象**：调度任务在容器重启后未自动启动。
- **根因**：`BackgroundScheduler` 需要在应用生命周期中启动/停止。
- **方案**：在 `@asynccontextmanager lifespan` 中调用 `start_scheduler()`（启动时）和 `stop_scheduler()`（关闭时）。调度器不阻塞 FastAPI 的事件循环。

## 18. 多对多关联表定义顺序

- **现象**：`Table` 创建时找不到另一个模型的 metadata。
- **根因**：SQLAlchemy 要求关联表在 `relationship` 使用前已注册到 `Base.metadata`。
- **方案**：关联表 `Table` 的定义放在独立的 `item_tag.py` 中，`Item` 和 `Tag` 模型都 `from app.models.item_tag import item_tag_assoc`。注意 `Item` 中的 `lazy="selectin"` 避免 N+1 查询。

## 19. pydantic-settings 多行 .env 值

- **现象**：`.env` 文件中 PEM 密钥等多行值解析失败。
- **根因**：`python-dotenv` 不支持跨行值。PEM 格式含换行符会解析中断。
- **方案**：将多行值编码为 base64（单行），代码中解码。或者将密钥存为独立文件（本项目 VAPID 密钥存 `data/vapid.json`，由程序自动生成和管理）。


## 20. `.card` 基类 `flex-wrap: wrap` + 列方向子容器 → 子项高度被拉伸

- **现象**（v0.9.13 修复）：添加页「数量与状态」分组区域过高，内容只有 93px 却显示 215px；页面总高异常。
- **根因**：`.card` 基类自带 `display: flex; flex-wrap: wrap`。`.add-form` 覆盖为 `flex-direction: column` 但未改 `flex-wrap`——**Chromium 下 column flex + wrap 会把每个 flex item（fieldset）的高度拉伸到 ~220px**（div 同理，与内容无关）。
- **方案**：列方向子容器必须显式 `flex-wrap: nowrap`（`.add-form { flex-direction: column; flex-wrap: nowrap; }`）。其他 `.card`（筛选栏等）保留 wrap 是期望行为。
- **排查思路**：先量内容子元素的 top/bottom，若组高 >> 内容高，把容器从 flex 父级里拿出来对比（离开 flex 后正常 = flex 容器问题，而非元素自身问题）。

## 21. 表单必填校验：`required` 属性会拦截 submit 事件（破坏程序弹窗规范）

- **现象**（v0.9.12）：表单加 `required` 后，点击提交不触发 `onsubmit`，自定义 `showDialog` 弹窗不出现，弹出的是浏览器原生气泡。
- **根因**：浏览器约束校验在 submit 事件派发前拦截空必填项。
- **方案**：项目规范是程序弹窗（nativeDialogs=0）——表单加 `novalidate` 属性，全部校验手写进 `onsubmit`（先名称 → 位置 → 照片，各自 `showDialog` 提示）。`required` 属性可保留作语义标记，但不参与原生校验。

## 22. `transition: all` 的元素，断言计算样式必须等过渡结束

- **现象**（v0.9.11 调试）：给按钮加 `.active` 类后立即 `getComputedStyle` 读颜色/粗细，得到的是旧值；甚至 inline `style.color='red'` 也不生效，误判为「CSS 没匹配」。
- **根因**：`transition: all 0.12s ease` 下，样式变更后的计算样式返回**过渡动画的起始值**，要等动画结束才到目标值。
- **方案**：测试脚本在切换样式后 `await sleep(250ms)` 再断言；排查顺序先查 transition 再怀疑级联/优先级。
