# 踩坑与排错（TROUBLESHOOTING）

记录开发 / 部署中遇到的真实问题。**遇到新坑请追加到对应条目或新增条目**，方便回溯。

---

## 1. SQLite + Docker 卷写入权限

- **现象**：容器内报 `sqlite3.OperationalError: unable to open database file` 或只读错误。
- **根因**：宿主机 `./data` 挂载进容器后，容器内进程（非 root 或权限不匹配）无写权限。
- **方案**：`Dockerfile` 中 `RUN mkdir -p /app/data && chmod 777 /app/data`；`docker-compose.yml` 用 `./data:/app/data` 持久化。本地直接运行时确保 `data/` 目录存在且可写。

## 2. 静态文件与 `/api` 路由冲突

- **现象**：访问 API 返回 HTML，或前端资源 404。
- **根因**：`StaticFiles` 挂载在 `/` 会兜底所有未匹配路径，若在 API 路由**之前**挂载会吞掉 `/api/*`。
- **方案**：`app.mount("/", StaticFiles(...))` **必须放在所有 `include_router` 之后**（`app/main.py` 已是此顺序）。

## 3. CORS 跨域（安卓端远程调用）

- **现象**：浏览器/安卓端调 API 报 CORS 错误，或带凭据时被浏览器拒绝。
- **根因**：`allow_credentials=True` 与 `allow_origins=["*"]` 同时存在时，带凭据的请求会被浏览器拒绝。
- **方案**：同源（网页与 API 同域）无影响；安卓端跨域时把 `.env` 的 `CORS_ORIGINS` 设为具体域名（逗号分隔），**不要**用 `*`。生产环境务必收紧。

## 4. passlib + bcrypt 版本兼容（已解决）

- **现象**：`passlib 1.7.4` + `bcrypt 5.0` 下，注册/登录抛 `ValueError: password cannot be longer than 72 bytes`，并伴随 `AttributeError: module 'bcrypt' has no attribute '__about__'` 警告。
- **根因**：bcrypt 5.x 改了底层 API 且强制 72 字节限制，passlib 1.7.4（多年未更新）未能适配，错误构造了待哈希内容。
- **方案（已采用）**：改用 passlib 内置 `pbkdf2_sha256`，不依赖外部 `bcrypt`，无长度限制。`app/core/security.py` 中 `CryptContext(schemes=["pbkdf2_sha256"])`；`requirements.txt` 仅保留 `passlib>=1.7.4`（去掉 `[bcrypt]`）。
- 若坚持 bcrypt，可固定 `bcrypt==4.0.1`；但 pbkdf2 对本项目（本地/内网）已足够安全且零外部依赖。

## 5. JWT 过期与刷新

- **现象**：登录一天后请求 401。
- **根因**：`ACCESS_TOKEN_EXPIRE_MINUTES` 默认 1440（1 天），当前无刷新令牌。
- **方案**：延期可改 `.env` 的 `ACCESS_TOKEN_EXPIRE_MINUTES`；长期方案在 v0.5+ 引入 refresh token。

## 6. 日期 / 时区

- **现象**：保质期显示偏差或解析失败。
- **根因**：`expiry_date` 用服务端 `date`（无时区），前端传 ISO 字符串（`YYYY-MM-DD`）；FastAPI 按服务端时区解释。
- **方案**：前端 `<input type="date">` 直接提交 ISO 字符串即可；多时区场景需后续统一时区处理。

## 7. pydantic-settings 读取 `.env`

- **现象**：本地改了 `.env` 不生效。
- **根因**：`Settings` 优先读**环境变量**（docker-compose 的 `environment`）；`.env` 仅本地未设环境变量时生效，且路径相对**工作目录**（`/app`）。
- **方案**：容器部署改 `docker-compose.yml` 的 `environment`；本地改 `.env` 需从项目根目录启动。

## 8. 中文枚举值存储

- **现象**：状态字段存入/读出异常。
- **根因**：`ItemStatus` 用 `str, enum.Enum`，值为中文（`"在库"` 等）。SQLAlchemy 存字符串值，Pydantic 按值匹配。
- **方案**：保持前后端都用同一套中文值；新增状态在 `app/models/status.py` 同步枚举与前端 `STATUS_OPTIONS`。
